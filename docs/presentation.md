# 汇报提纲（约 15–20 分钟）

> 原则：先讲清"解决谁的什么问题"，再讲"怎么做的、为什么这么取舍"，用数据和现场演示说话。

## 1. 问题理解（2 分钟）
- **谁在用**：不是主播本人（直播时没空看屏幕），而是**场控 / 运营 / 同时管多个直播间的品牌方**。
- **他们要什么**：问题发生后**一分钟内**知道，并且拿到一句能直接转告主播的话。
- **问题分三层，按价值排序**：
  1. 合规风险（违禁词、功效夸大、虚构紧迫）—— 后果最严重：限流、封禁、罚款
  2. 话术缺失（不报价、不讲售后、只逼单不讲产品）—— 影响转化
  3. 表达质量（语速、冷场、口头禅）—— 影响体验
- **一个关键产品判断**：误报比漏报更伤——告警一多，场控就不看了。所以"去重、分级、附证据"是核心功能，不是锦上添花。

## 2. 现场演示（5 分钟）
1. 粘贴韩束直播间链接 → 实时转写开始滚动（如未开播，用录制样本 10 倍速回放）
2. 指出：违禁词秒级标红 + 弹窗（"全部改善"）
3. 一分钟后：语速卡片变红（380+ 字/分），告警出现；第二次出现变成 ×2，而不是刷屏
4. AI 分析：阶段覆盖清单（哪些讲了、哪些缺了）、问题附原文证据和"提示主播"的话、话术评分
5. 打开话术框架编辑器：框架是可配置的 YAML，换品类只改配置
6. 复盘报告
7. （可选）同时开第二个直播间，展示多直播间标签页

**备用**：提前录好演示视频，防止现场网络或直播间状态出问题。

## 3. 架构（2 分钟）
展示 README 中的架构图，一句话讲清每层：
数据源抽象 → ffmpeg 统一音频格式 → VAD + SenseVoice 本地识别 → 规则层（实时）+ LLM 层（每分钟）→ 去重 → 界面

## 4. 关键取舍（4 分钟，重点）
挑 4–5 个讲透，每个讲"选了什么 / 放弃了什么 / 为什么 / 代价"：

| 取舍 | 一句话 |
|---|---|
| **规则 + LLM 分层** | 能确定性计算的（语速、冷场、违禁词）本地算：零成本、秒级、可解释；需要理解语义的（阶段缺失、虚构紧迫）交给 LLM。例子："郑总临时加的"→"王总来炸福利"，词库抓不住变体，LLM 可以 |
| **本地 SenseVoice vs 云端 ASR** | 免费、隐私、离线可用，RTF 0.033 可单机并发多直播间；代价是不支持热词（用纠错表补）、句长级延迟（对 1 分钟分析周期可接受） |
| **两种分析粒度** | 表达指标看最近 1 分钟（及时、不重复）；话术结构看最近 5 分钟（需要上下文）。5 分钟窗口每分钟滑动一次，同一段话会被分析 5 次 → 必须按问题编码去重 |
| **音频时间作为时钟** | 直播 / 回放 / 倍速 / 断流重连共用一套调度，不会误报冷场 |
| **pywebview 而非 Electron** | 单一 Python 技术栈，系统自带 WebView，包小；同一界面可在浏览器调试 |
| **LLM 输出约束** | JSON mode + 固定问题编码 + 必须附原文证据 + 最多 5 条，换来可去重、可统计、少幻觉 |
| **告警去重粒度（最有说服力的一条，有三轮数据）** | 只按编码合并：30 条/30 分钟，但"虚构央视报道""保价三年三倍退款"被吞掉；全按证据：83 条，太吵；最终区分**事件型**（合规，每个新说法单独提醒）和**状态型**（持续逼单、没报价，提醒一次累加次数）：45 条，新风险全部可见 |

## 5. 遇到的问题（3 分钟）
挑最能体现排查能力的几个（详见 devlog）：
1. **冷场误报**：VAD 还没切出的那句被当成了沉默 → 查询 VAD 是否仍在讲话
2. **语速虚高 559**：跨窗口边界的长句字数没有按比例分摊
3. **10 倍速只有 1.8 倍**：对照实验定位到 ffmpeg `-readrate` 异常 → 节奏控制移到自己的代码里
4. **AI 把识别错误当成主播的问题**："100 毫升"被识别成"100 瓶"，AI 报"规格混乱"。提示词提醒无效 → 加 `asr_suspect` 自检字段，有改善但不稳定。诚实结论：提示词治标，根本要靠更好的 ASR 和评估集
5. **告警去重三轮迭代**（见取舍表）

共同点：**代码"能跑"不等于"对"，要用真实数据检查数值是否合理。**

## 6. Vibe Coding 方法（2 分钟）
- 先人工定范围和架构，再让 AI 按模块实现
- 每个模块写最小测试脚本，用真实样本跑，看数字是否合理
- AI 给的"经验性结论"（如各档清晰度音频是否相同）要实测验证后才写进文档
- 人负责：需求取舍、模块边界、Prompt 中的职责划分、验证

## 7. 局限与下一步（1 分钟）
- LLM 准确率需要人工标注样本定量评估
- 接入支持热词的云端 ASR 做对比
- 说话人分离（主播 / 助播）
- 系统音频采集，兜底支持任意平台
- 打包安装程序
- 结合弹幕和成交数据，验证话术问题与转化的关系

## 可能被追问的问题
- **成本**（实测）：每次输入约 2365 token（93% 命中缓存）、输出约 760 token；deepseek-flash 下每个直播间**高峰约 0.39 元/小时、空闲约 0.20 元/小时**；输出占成本 90% 以上，可继续压缩输出字段
- **延迟**（实测）：违禁词 = 句长（7–25 秒）；表达指标 ≤ 1 个周期；LLM 单次 4.7～4.9 秒（最长 6.9 秒），远小于 60 秒周期
- **AI 准不准**：已定性验证（30 分钟样本中发现的问题与人工听感一致，附原文证据）；尚未定量评估，下一步人工标注样本算精确率 / 召回率
- **怎么支持其他平台**：实现一个 `StreamSource` 子类；或用系统音频采集兜底
- **风控**：只在启动和重连时调用接口，频率很低；被封时可切换系统音频采集
- **为什么不直接把音频给多模态大模型**：成本高、延迟高、不可控；先转文字再分析，每层可单独评估和替换
